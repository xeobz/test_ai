# AI-помощник для подготовки товарных описаний (B2B КИПиА)

Прототип сервиса генерации черновиков карточек товаров для B2B-интернет-магазина промышленного оборудования и контрольно-измерительных приборов.

Сервис принимает входные технические данные (название, производитель, спецификации, фрагмент паспорта) в формате **JSON** или через **веб-форму** и формирует готовую карточку товара с защитой от выдумывания характеристик (Zero-Hallucination) и аудитом полноты данных.

---

## 📌 Возможности сервиса

1. **Строгая валидация и защита от галлюцинаций:**
   - Модель оперирует **только** фактами из входных данных.
   - Если важная техническая характеристика отсутствует, в спецификации принудительно ставится отметка: `данных нет`.
   - Запрещено придумывать численные диапазоны, интерфейсы или материалы.
2. **Аудит полноты данных (`data_completeness`):**
   - Двухуровневая детекция пропусков (эвристика + LLM): выявляет отсутствие критических для инженера параметров (диапазон измерений, класс точности, рабочая температура, питание) и формирует перечень вопросов поставщику.
3. **Генерация полного комплекта для контент-менеджера:**
   - **SEO-заголовок (Title):** строго до 70 символов с защитной программной обрезкой.
   - **SEO-описание (Description):** связный B2B-текст объёмом от 800 до 1 200 символов.
   - **Список ключевых характеристик:** структурированная таблица параметров.
   - **3–5 целевых поисковых запросов:** коммерческие ключи для оптимизации страницы.
   - **Commercial-блок:** целевая аудитория, применимость в отраслях и решаемые задачи для менеджеров по продажам.
4. **Два интерфейса использования:**
   - **Веб-интерфейс:** современная SPA-страница с переключением JSON / Форма, пресетами готовых приборов и копированием в 1 клик (Markdown / JSON).
   - **CLI-утилита:** запуск пакетной обработки через консоль.

---

## 🛠 Технологический стек

- **Язык:** Python 3.10+
- **Веб-фреймворк:** FastAPI + Uvicorn
- **Валидация данных:** Pydantic v2 + pydantic-settings
- **LLM-интеграция:** OpenRouter API / OpenAI API (асинхронный клиент на `httpx` с retry-логикой)
- **Шаблонизатор / UI:** Jinja2, Bootstrap 5, Bootstrap Icons
- **Тестирование:** Pytest

## 🚀 Быстрый старт

### 1. Клонирование и установка зависимостей

```bash
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
cd ai-product-card-generator

# Создание и активация виртуального окружения
python -m venv venv
# Windows:
venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

# Установка зависимостей
pip install -r requirements.txt
```

### 2. Настройка переменных окружения

Скопируйте пример файла конфигурации:
```bash
cp .env.example .env
```
Откройте `.env` и укажите ваш API-ключ. По умолчанию настроен OpenRouter:
```env
LLM_PROVIDER=openrouter
OPENROUTER_API_KEY=ваш_ключ_openrouter
OPENROUTER_MODEL=openai/gpt-4o-mini
```
*(Также поддерживается прямое подключение к OpenAI через `LLM_PROVIDER=openai` и `OPENAI_API_KEY`).*

## 💻 Использование

### Вариант А: Запуск веб-сервиса (рекомендуется)

```bash
uvicorn app.main:app --reload --port 8000
```
Откройте в браузере: **http://127.0.0.1:8000**

В интерфейсе доступны:
- Кнопки быстрой загрузки тестовых приборов: **«Пример 1 (Манометр)»**, **«Пример 2 (Датчик АИР-20)»**, **«Неполные данные (ТСП)»**.
- Режим ввода: через JSON-редактор или через поля формы.
- Копирование черновика карточки в буфер обмена в формате **Markdown** или **JSON**.

### Вариант Б: Запуск через консоль (CLI)

```bash
# Вывод в формате Markdown:
python main.py --file examples/product_1_manometer.json

# Вывод в формате JSON:
python main.py --file examples/product_2_sensor.json --format json
```

### Вариант В: Запуск тестов

```bash
pytest tests/
```

## 🧠 Описание промптов и архитектурных решений

1. **System Prompt с системной изоляцией (Grounding):**
   - Промпт жестко инструктирует модель быть техническим редактором B2B-каталога.
   - Запрещены рекламные штампы («лучший в мире», «непревзойденный») и любые домыслы о материалах или диапазонах.
2. **Структурированный вывод (JSON Mode + Pydantic v2):**
   - Вывод модели форсируется через `response_format: {"type": "json_object"}`.
   - Ответ проходит автоматическую валидацию строгой схемой `ProductCardDraft`.
3. **Защитная программная постобработка (Guards):**
   - Если модель по какой-либо причине превысила ограничение в 70 символов для заголовка, срабатывает детерминированная обрезка по границе последнего слова с очисткой пунктуации.
4. **Retry и Circuit Breaker:**
   - Вызовы к LLM обернуты в механизм повторных попыток с экспоненциальной задержкой на случай кратковременных сетевых сбоев.

## ⚠️ Ограничения решения и вектор развития

### Текущие ограничения MVP:
- Обработка единичных товаров за один вызов (нет фонового пакетного импорта из Excel/CSV на 10 000 позиций).
- Опора на текстовые данные паспорта (нет встроенного OCR для сканированных PDF-паспортов со схемами подключения).

### Возможные улучшения для промышленной эксплуатации:
1. **RAG по нормативной базе:** подключение векторной базы ГОСТов (например, ГОСТ 2405-88 для манометров) для автоматической валидации корректности единиц измерения и обозначений.
2. **Пакетный конвейер:** интеграция очереди задач (Celery / Redis / RQ) для фоновой генерации каталогов из 1С / Bitrix24 с вебхуками оповещения.
3. **Мультимодальный вход:** добавление распознавания чертежей приборов и сканов паспортов через Vision API.
4. **A/B тестирование промптов:** логирование оценок контент-менеджера для дообучения Few-Shot примеров.
